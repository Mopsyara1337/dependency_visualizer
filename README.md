# Dependency Visualizer

Консольное приложение на Python для анализа и визуализации
графа зависимостей пакетов Ubuntu (APT).

Программа разрабатывается в рамках практической работы №2
по дисциплине «Конфигурационное управление».

## Описание

Приложение предназначено для получения информации о зависимостях
программных пакетов из репозиториев Ubuntu, построения графа
зависимостей и его визуализации.

Разработка выполняется поэтапно.

### Этап 1. Минимальный прототип с конфигурацией

На данном этапе реализованы:

- Загрузка конфигурации из TOML-файла.
- Проверка наличия обязательных параметров.
- Проверка типов параметров.
- Проверка строковых параметров на пустые значения.
- Проверка URL репозитория.
- Проверка существования файла тестового репозитория.
- Проверка имени и расширения выходного PNG-файла.
- Обработка ошибок конфигурации.
- Вывод параметров в формате ключ-значение.

Получение зависимостей и построение графа будут реализованы
на следующих этапах.

## Требования

- Python 3.11 или новее.
- Windows для запуска через run.bat.

Используются только стандартные библиотеки Python.

## Конфигурация

Параметры программы задаются в файле `config.toml`,
расположенном в корневой директории проекта.

Пример конфигурации:

```toml
package = "bash"
repository = "https://archive.ubuntu.com/ubuntu/"
test_mode = false
output_file = "graph.png"
```

### Параметры конфигурации

| Параметр | Тип | Описание |
|----------|-----|----------|
| package | str | Название анализируемого пакета |
| repository | str | URL репозитория или путь к тестовому файлу |
| test_mode | bool | Режим работы с тестовым репозиторием |
| output_file | str | Имя выходного PNG-файла |

При `test_mode = false` параметр `repository` должен
содержать URL с протоколом HTTP или HTTPS.

При `test_mode = true` параметр `repository` должен
содержать путь к существующему локальному файлу.

Параметр `output_file` должен содержать имя файла
с расширением `.png` без пути к директории.

## Реализованные функции

- `load_config()` — загрузка конфигурации из TOML-файла.
- `validate_config(config)` — общая проверка параметров конфигурации.
- `validate_repository(config)` — проверка URL или пути к тестовому файлу.
- `validate_output_file(config)` — проверка имени выходного файла.
- `print_config(config)` — вывод параметров в формате ключ-значение.
- `main()` — запуск программы и обработка ошибок.

## Запуск программы

Для запуска программы через командную строку Windows:

```bat
run.bat
```

Скрипт использует Python из виртуального окружения `.venv`,
если оно существует. В противном случае используется
Python, доступный в системе.

Также программу можно запустить непосредственно:

```bash
python src/main.py
```

Компиляция проекта не требуется.

## Примеры использования

### Корректная конфигурация

При использовании приведённого выше `config.toml`
программа выводит:

```text
package = bash
repository = https://archive.ubuntu.com/ubuntu/
test_mode = False
output_file = graph.png
```

### Отсутствующий параметр

Если удалить параметр `package`, программа выведет:

```text
Ошибка конфигурации: Отсутствует параметр package
```

### Некорректный тип

Если указать:

```toml
test_mode = "false"
```

Программа сообщит о неправильном типе параметра.

### Некорректное расширение файла

Если указать:

```toml
output_file = "graph.txt"
```

Программа выведет:

```text
Ошибка конфигурации: Неверное расширение выходного файла
```

## Тестирование

На первом этапе выполнено ручное тестирование
загрузки и проверки конфигурации.

Проверены следующие ситуации:

- Корректная конфигурация.
- Отсутствие конфигурационного файла.
- Некорректный синтаксис TOML.
- Отсутствие обязательных параметров.
- Неправильные типы значений.
- Пустые строковые параметры.
- Некорректный URL репозитория.
- Отсутствие тестового файла.
- Некорректное имя выходного файла.
- Неправильное расширение выходного файла.

Автоматизированные тесты будут добавлены
на следующих этапах разработки.
