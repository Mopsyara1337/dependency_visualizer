# Dependency Visualizer

Консольное приложение на Python для анализа и визуализации
графа зависимостей пакетов Ubuntu (APT).

Программа разрабатывается в рамках практической работы №2
по дисциплине «Конфигурационное управление».

## Описание

Приложение предназначено для получения информации о зависимостях
программных пакетов из репозиториев Ubuntu, построения графа
зависимостей и его визуализации.

Разработка выполняется поэтапно.

## Реализованные этапы

### Этап 1. Минимальный прототип с конфигурацией

Реализованы следующие возможности:

- Загрузка конфигурации из TOML-файла.
- Проверка наличия обязательных параметров.
- Проверка типов параметров.
- Проверка строковых параметров на пустые значения.
- Проверка URL репозитория.
- Проверка существования файла тестового репозитория.
- Проверка имени и расширения выходного PNG-файла.
- Обработка ошибок конфигурации.
- Вывод параметров в формате ключ-значение.

### Этап 2. Сбор данных

Реализовано получение информации о прямых зависимостях пакетов Ubuntu
из удалённого репозитория.

Основные возможности:

- Загрузка индекса пакетов `Packages.gz` по HTTP/HTTPS.
- Распаковка полученных данных с помощью gzip.
- Поиск заданного пакета в индексе репозитория.
- Извлечение обычных зависимостей `Depends`.
- Извлечение предварительных зависимостей `Pre-Depends`.
- Обработка многострочных полей зависимостей.
- Разделение зависимостей на группы с сохранением альтернатив.
- Выделение имён пакетов без ограничений версий и квалификаторов
  архитектуры.
- Вывод прямых зависимостей в консоль.
- Обработка ошибок HTTP, подключения, распаковки и поиска пакетов.

Получение информации реализовано средствами стандартной библиотеки
Python без использования менеджеров пакетов и сторонних библиотек
для определения зависимостей.

### Этап 3. Основные операции

Реализовано построение графа транзитивных зависимостей пакетов
с использованием алгоритма поиска в ширину (BFS).

Основные возможности:

- Построение полного графа достижимых зависимостей выбранного пакета.
- Использование BFS без рекурсии.
- Обход обычных (Depends) и предварительных (Pre-Depends) зависимостей.
- Сохранение альтернативных зависимостей.
- Обработка циклических зависимостей без бесконечного обхода.
- Исключение повторной обработки уже обнаруженных пакетов.
- Обработка пакетов, отсутствующих в индексе репозитория.
- Поддержка тестового режима с локальным файлом репозитория.
- Вывод информации о найденных и отсутствующих пакетах.

#### Алгоритм построения графа

Для построения графа используется алгоритм BFS, реализованный
с помощью очереди `collections.deque`.

Перед началом обхода создаются:

- `graph` — словарь для хранения графа зависимостей.
- `queue` — очередь пакетов, ожидающих обработки.
- `visited` — множество уже обнаруженных пакетов.
- `missing_packages` — множество пакетов, отсутствующих в индексе.

Изначально в очередь помещается выбранный пакет.

На каждой итерации из очереди извлекается очередной пакет.
Для него определяются зависимости Depends и Pre-Depends,
которые сохраняются в графе.

Все ещё не обнаруженные зависимости добавляются в очередь
и множество visited.

При повторном обнаружении пакета он не добавляется в очередь,
однако соответствующая связь сохраняется в графе.
Это позволяет корректно обрабатывать циклические зависимости.

Обход завершается после опустошения очереди.

#### Структура графа

Граф хранится в виде словаря, где каждому пакету
соответствуют две категории зависимостей.

Пример:

```python
graph = {
    "A": {
        "Depends": [["B", "C"], ["D"]],
        "Pre-Depends": [["E"]]
    },
    "B": {
        "Depends": [["F"]],
        "Pre-Depends": []
    }
}
```

Каждый внутренний список содержит альтернативные пакеты.
Например, группа `["B", "C"]` обозначает зависимость
от B или C.

При построении графа рассматриваются все альтернативы.
Информация об их взаимозаменяемости при этом сохраняется.

Пакеты, отсутствующие в индексе, сохраняются отдельно
в множестве `missing_packages`. Связи с такими пакетами
остаются в графе, но дальнейший обход их зависимостей
не выполняется.

#### Индексация пакетов

Для ускорения поиска записей реализована предварительная
индексация репозитория.

Все записи пакетов преобразуются в словарь, где ключом
является название пакета, а значением — его метаданные.

Это позволяет получать информацию о пакете по имени
без повторного последовательного просмотра всего репозитория.

Средняя вычислительная сложность поиска записи
в словаре составляет O(1).

### Этап 4. Дополнительные операции

Реализован поиск прямых и транзитивных обратных зависимостей
заданного пакета с использованием алгоритма BFS.

Обратными зависимостями называются пакеты, которые прямо
или косвенно зависят от выбранного пакета.

#### Построение обратного графа

Для определения обратных зависимостей формируется отдельный
граф с противоположным направлением связей.

Алгоритм последовательно обрабатывает все пакеты репозитория,
извлекает поля Depends и Pre-Depends и добавляет обратные
связи в словарь.

Обратный граф хранится в виде словаря, где ключом является
название пакета, а значением — множество пакетов, которые
от него непосредственно зависят.

Пример:

```python
reverse_graph = {
    "A": set(),
    "B": {"A"},
    "C": {"A", "B"}
}
```

Для исключения дублирования связей используются множества set.

Вычислительная сложность построения обратного графа
составляет O(V + E), без учёта дополнительных затрат
на чтение и разбор текстовых метаданных.

#### Поиск транзитивных обратных зависимостей

Для поиска используется алгоритм BFS с очередью deque
и множеством посещённых пакетов visited.

Обход начинается с выбранного пакета. На каждой итерации
из очереди извлекается очередная вершина, после чего
в очередь добавляются ещё не посещённые пакеты,
которые зависят от неё.

Использование множества visited предотвращает
повторную обработку вершин и бесконечный обход циклов.

Выбранный пакет исключается из итогового множества
обратных зависимостей.

Результат выводится в консоль в алфавитном порядке.

При анализе учитываются обычные, предварительные
и альтернативные зависимости.

Поскольку рассматриваются все альтернативы,
результат включает потенциальные обратные зависимости.

## Требования

- Python 3.11 или новее.
- Windows для запуска через `run.bat`.
- Подключение к интернету для работы с репозиториями Ubuntu.

Для работы приложения используются только стандартные библиотеки Python.

## Конфигурация

Настройки программы задаются в файле `config.toml`,
расположенном в корневой директории проекта.

Пример конфигурации:

```toml
package = "bash"
repository = "https://archive.ubuntu.com/ubuntu/"
test_mode = false
output_file = "graph.png"
```

### Параметры конфигурации

| Параметр | Тип | Описание |
|----------|-----|----------|
| package | str | Название анализируемого пакета |
| repository | str | URL репозитория или путь к тестовому файлу |
| test_mode | bool | Режим работы с тестовым репозиторием |
| output_file | str | Имя выходного PNG-файла |

При `test_mode = false` параметр `repository` должен содержать
корректный URL с протоколом HTTP или HTTPS.

При `test_mode = true` параметр `repository` должен содержать
путь к существующему локальному файлу.

### Режимы работы

Программа поддерживает два режима получения данных.

**Обычный режим (`test_mode = false`)**

Информация о пакетах загружается из удалённого репозитория Ubuntu
по протоколу HTTP или HTTPS.

**Тестовый режим (`test_mode = true`)**

Информация о пакетах считывается из локального текстового файла,
путь к которому указывается в параметре `repository`.

Тестовый файл использует формат записей пакетов Ubuntu.
Названия тестовых пакетов задаются большими латинскими буквами.

Пример конфигурации для тестового режима:

```toml
package = "A"
repository = "tests/test_cycles.txt"
test_mode = true
output_file = "graph.png"
```

Пути к тестовым файлам указываются относительно корневой
директории проекта.

В обоих режимах используется один алгоритм построения графа.

Параметр `output_file` должен содержать имя файла
с расширением `.png` без пути к директории.

Создание PNG-файла будет реализовано на пятом этапе.

## Реализованные функции

### main.py

- `load_config()` — загрузка конфигурации из TOML-файла.
- `validate_config(config)` — общая проверка параметров конфигурации.
- `validate_repository(config)` — проверка URL или пути к репозиторию.
- `validate_output_file(config)` — проверка имени выходного файла.
- `prepare_config()` — загрузка и проверка конфигурации с обработкой ошибок.
- `load_packages_data(config)` — выбор источника данных в зависимости от режима.
- `prepare_package(config)` — загрузка данных и создание индекса пакетов.
- `main()` — управление выполнением программы.

### packages.py

- `fetch_packages()` — загрузка индекса пакетов из репозитория Ubuntu.
- `build_package_index()` — создание словаря пакетов для быстрого поиска.
- `get_dependencies()` — извлечение полей Depends и Pre-Depends.
- `parse_dependencies()` — разделение зависимостей на группы.
- `extract_package_name()` — выделение имени пакета из зависимости.

### graph.py

- `build_dependency_graph()` — построение графа транзитивных зависимостей
  алгоритмом BFS с обработкой циклов и отсутствующих пакетов.
- `build_reverse_graph(package_index)` — построение обратного
  графа зависимостей всех пакетов репозитория.
- `find_reverse_dependencies(reverse_graph, package_name)` —
  поиск прямых и транзитивных обратных зависимостей через BFS.

Для запуска через командную строку Windows:

```bat
run.bat
```

если оно существует. В противном случае используется

```bash
python src/main.py
```

## Примеры использования

### Получение зависимостей bash

Конфигурация:

```toml
package = "bash"
repository = "https://archive.ubuntu.com/ubuntu/"
test_mode = false
output_file = "graph.png"
```

Результат получения зависимостей:

```text
Пакет: bash

Прямые зависимости (Depends):
- base-files
- debianutils

Предварительные зависимости (Pre-Depends):
- libc6
- libtinfo6
```

### Альтернативные зависимости

Если пакет содержит альтернативные зависимости, они
выводятся через символ `|`.

Пример:

```text
- base-passwd | adduser
```

Это означает, что зависимость может быть удовлетворена
одним из указанных пакетов.

### Несуществующий пакет

Если в конфигурации указать:

```toml
package = "nonexistent-package-12345"
```

Программа выведет сообщение:

```text
Ошибка поиска пакета: Пакет nonexistent-package-12345 не найден в репозитории
```

## Тестирование

### Этап 1

Выполнено ручное тестирование загрузки конфигурации.

Проверены:

- Корректная конфигурация.
- Отсутствие конфигурационного файла.
- Некорректный синтаксис TOML.
- Отсутствие обязательных параметров.
- Неправильные типы параметров.
- Пустые строковые значения.
- Некорректный URL репозитория.
- Отсутствие тестового файла.
- Некорректное имя выходного файла.

### Этап 2

Выполнено ручное тестирование получения зависимостей.

Проверена загрузка индекса пакетов с нескольких зеркал Ubuntu.

Проверены пакеты:

- `bash` — обычные и предварительные зависимости.
- `coreutils` — отсутствие Depends и наличие Pre-Depends.
- `apt` — обычные зависимости, включая альтернативные.
- `nonexistent-package-12345` — обработка отсутствующего пакета.

Также проверена обработка ошибок подключения и HTTP.

Автоматизированные тесты пока не реализованы.

### Этап 3

Выполнено ручное тестирование алгоритма BFS
и работы с локальными тестовыми репозиториями.

Для тестирования подготовлены три файла в директории `tests`.

| Файл | Проверяемые ситуации |
|------|----------------------|
| test_cycles.txt | Циклические и общие зависимости |
| test_alternatives.txt | Альтернативные и предварительные зависимости |
| test_missing.txt | Отсутствующие пакеты и пакеты без зависимостей |

#### Тест 1. Циклические зависимости

Файл: `tests/test_cycles.txt`

Начальный пакет: A.

В репозитории присутствует цикл A → B → D → A,
а также общая зависимость D для пакетов B и C.

Результаты:

- Найдено пакетов: 4.
- Отсутствующих пакетов: 0.
- Обход завершён без зацикливания.
- Циклическая связь D → A сохранена.

#### Тест 2. Альтернативные зависимости

Файл: `tests/test_alternatives.txt`

Начальный пакет: A.

Пакет A содержит альтернативную зависимость B или C,
обычную зависимость D и предварительную зависимость E.

Пакеты B и E имеют общую зависимость F.

Результаты:

- Найдено пакетов: 6.
- Отсутствующих пакетов: 0.
- Альтернативы B и C сохранены в одной группе.
- Предварительная зависимость E обработана.
- Пакет F обработан только один раз.

#### Тест 3. Отсутствующие пакеты

Файл: `tests/test_missing.txt`

Начальный пакет: A.

В репозитории отсутствует пакет X, который встречается
в нескольких зависимостях.

Пакеты C и E существуют, но не имеют зависимостей.

Результаты:

- Найдено пакетов: 5.
- Отсутствующих пакетов: 1.
- Пакет X добавлен в missing_packages.
- Связи с X сохранены.
- Пакеты без зависимостей обработаны корректно.

Дополнительно проверена обработка ошибки при указании
несуществующего начального пакета Z.

#### Проверка на реальном репозитории

## Ограничения текущей реализации

На втором этапе используется индекс пакетов:

`dists/noble/main/binary-amd64/Packages.gz`

Таким образом, анализ ограничен Ubuntu 24.04 (Noble),
компонентом `main` и архитектурой `amd64`.

При обработке зависимостей выделяются имена пакетов.
Ограничения версий и квалификаторы архитектуры не учитываются
при определении имён зависимостей.

Альтернативные зависимости сохраняются в отдельных группах,
однако полноценное разрешение зависимостей средствами APT
не выполняется.

Построение графа транзитивных зависимостей и тестовый режим
реализованы на третьем этапе.

Программа сохраняет альтернативные зависимости, но не выполняет
полноценное разрешение зависимостей с учётом версий, архитектур
и виртуальных пакетов.

Отсутствующие в индексе пакеты учитываются отдельно.
Их дальнейшие зависимости не исследуются.

Поиск прямых и транзитивных обратных зависимостей
реализован на четвёртом этапе.

Программа не выполняет полноценное разрешение
альтернативных и виртуальных пакетов средствами APT.

Формирование графического представления зависимостей
и сохранение результата в PNG будут реализованы
на пятом этапе.
